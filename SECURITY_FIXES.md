# OPENSTATION — отчёт об исправлениях

## Что изменено

В локальной копии закрыт неаутентифицированный сетевой доступ к `/api/*` и WebSocket: сервер создаёт случайный 256-битный bearer token и хранит его в `/data/local/openstation/webui.token` с режимом `0600`. Удалены wildcard CORS-заголовки, ограничено число HTTP-соединений, синхронизировано закрытие WebSocket с отправкой кадров. В статусном JSON маскируются Gemini API key и MQTT password; веб-пульт не подменяет сохранённые секреты пустыми значениями.

Ассистент больше не получает инструмент произвольных root-команд; устаревший `shell_exec` завершается отказом, а `reboot` отключён для вызовов модели. Удалён динамический Android broadcast для вставки текста, UDP-плеер и IME слушают loopback. HTTP-клиент не переносит Authorization/Cookie/API-key заголовки при redirect на другой origin. Исправлены OTA deadlock в ветке «уже обновлено» и гонка между применением конфигурации через HTTP/MQTT.

Сервисный флешер теперь требует корректный manifest, сверяет точный размер и SHA-256 ROM-образов с manifest репозитория и прекращает работу при ошибке записи/finalization вместо ложного сообщения об успехе. Неизвестный выбор, отсутствие GUI или пустой путь к ZIP отменяют операцию. Подпись USB-драйвера ограничена ожидаемыми SHA-256 и signer thumbprint; сбой `pnputil` считается ошибкой, а непроверенный `InstallDriver.exe` не запускается. Исправлены path traversal в подготовке ASAR, проверка exit code GUI-флешера и запись APK rollback-журнала до переименования. OTA deploy сравнивает SHA-256 и заменяет каталог плеера с сохранением предыдущей версии до успешного переключения. Отдельный режим `-InstallDriver` завершается после установки и больше не продолжает к прошивке ROM.

Согласована локальная версия-кандидат v1.3.6: `openstationd`, Launcher, IME, OTA manifest, README и deploy script используют одинаковую версию. Android `versionCode` увеличен с 7 до 8 для Launcher и с 6 до 7 для IME. В vendored Mbed TLS добавлена проверка наличия optional framework helper до запуска диагностического Python probe, предотвращающая traceback при неполном vendor checkout.

## Проверки и статус выпуска

CMake/Ninja собрали оптимизированный AArch64 `openstationd`; Gradle `assembleDebug` собрал оба Android APK. `apksigner verify`, `aapt` и `llvm-readelf` подтвердили подпись debug APK, package/version metadata и ABI AArch64. Размеры и SHA-256 четырёх файлов в локальном manifest совпали. После guard-а повторная сборка прошла без Mbed TLS traceback; остаётся предупреждение SDK tools/AGP о разнице версий XML metadata (v4 против поддерживаемой v3), оно сборку не остановило.

`testDebugUnitTest` завершился успешно для обоих модулей, но задач с тестовым исходным кодом в проекте нет (`NO-SOURCE`). Прошли Python `py_compile`, PowerShell Parser для изменённых скриптов, `node --check` и `git diff --check`. Реальная OTA, прошивка и проверка на физической станции не выполнялись.

## Блокер подписи и публикации

Debug APK из локальной RC v1.3.6 подписаны сертификатом SHA-256 `77659745b9d1f6f4c56f6ab8655927c37dbc498799e98dacb6bfa99ead53b0d8`. APK из baseline проекта подписаны другим сертификатом `062dd585a51063bdf4a9591660b49be26f5b8f611db88a64215848258ce1bc7b`. Android отклонит новые APK как обновления поверх существующих приложений при несовпадении подписи. Репозиторий и стандартный пользовательский debug keystore старый private key не содержат.

Артефакты из `.work/release-candidate-v1.3.6-debug/` — только QA/debug, **не публиковать как OTA**. Владелец релиза должен подписать release APK оригинальным keystore, проверить fingerprint, обновить итоговый firmware manifest по уже подписанным файлам и проверить обновление на тестовой станции. GitHub push/release, публичная OTA и изменение устройства не выполнялись.

## Остаточный риск

Веб-сервер использует HTTP без TLS, поэтому bearer token может быть перехвачен в незашифрованной локальной сети; порт 8080 не следует публиковать в Интернет. Запросы с loopback оставлены без token для совместимости с Android-мастером настройки, так что локальное приложение на самой станции остаётся в границе доверия. Loopback UDP IPC не имеет криптографической аутентификации и защищает от удалённых хостов, но не от других приложений на устройстве. Сервисная прошивка не имеет автоматического rollback: сбой посреди записи может потребовать заводского восстановления. Установщик драйвера всё ещё добавляет закреплённый сертификат в хранилища доверия Windows — это привилегированное действие, ограниченное точным каталогом и thumbprint.
